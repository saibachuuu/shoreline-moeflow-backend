# 图片手动顺序

## 使用方式

项目文件页的“重建缩略图”同一工具栏新增“编辑顺序”。进入后仍在当前页面，显示根目录的全部图片，不受原分页、搜索词或勾选状态限制。

- 拖拽图片，或在图片下方选择目标序号；操作是移动插入，不是两张图片交换。
- 点击“保存顺序”才写入服务器；取消时丢弃本地草稿，有修改时会二次确认。
- “自动排序”按服务端默认文件名顺序生成预览，保存时清空手动顺序字段，恢复原有自动排序和无编号导出；取消不会改变已保存的顺序。即使画面顺序原本就与默认相同，仍可保存以清空手动顺序。
- 自动排序后继续拖拽或选择其他位置，会重新切换为自定义顺序草稿。
- 保存后文件列表、翻译器上一张/下一张、导出使用相同的图片顺序。
- 当前项目页本身仅展示根目录，本次不增加目录浏览、跨目录拖拽或文件夹重排功能。
- 权限限于有效的团队/项目创建者和管理员。只获得普通修改/成员管理权限的自定义身份不因此获得重排权限；已移除身份和只读项目不可编辑。前后端均有校验。

## 数据和兼容

`File.manual_order`（数据库 `mo`）是可空的正整数。旧数据不回填；未编辑的目录仍采用原来的目录/类型/文件名排序。仅打开、取消或未修改后提交不会初始化顺序。

保存手动变动时，为该目录全部有效图片写入 1..N。新上传到已编辑目录的图片追加到末尾；未编辑目录的新图片仍为空。重命名和覆盖同名图片保留位置，创建或切换修订版继承当前位置。移动到其他目录时按目标目录规则追加，目标目录未编辑则清空自身顺序。

启用手动顺序时，名称和 ID 用作相同顺序值的稳定兜底。文件夹/目录层级仍按旧规则处理，不跨目录混排。

`Project.file_order_lock`（数据库 `fol`）是重排请求间的短期互斥租约，不是业务顺序字段。编辑快照版本包含图片 ID、名称和顺序，防止旧页面直接覆盖其他人的修改。文件变更后保存会提示取消编辑并重新加载。该租约只串行化重排请求，不宣称提供跨上传、移动、删除等所有操作的数据库事务隔离。

## API

- `GET /v1/projects/{project_id}/files/order`：完整根目录图片快照 `{ files, version, default_file_ids }`。
- `PUT /v1/projects/{project_id}/files/order`：`{ file_ids: [...], version: "..." }`，必须包含全部根目录有效图片且无重复。可选 `reset_to_default: true` 用于清空手动顺序，同样校验权限和快照版本。
- 项目详情增加 `can_order_files`，文件数据增加 `manual_order`。

## 导出

当本次导出图片中存在非空手动顺序时，按本次导出的有效排列生成 `0001_原文件名`、`0002_原文件名`……；超过四位时自动扩展宽度。部分导出从 1 重新编号。

图片和 LabelPlus 文本共用同一份文件快照、编号映射，确保 ZIP 的 `images/` 文件名和 `translations.txt` 中的图片名称一致。混合旧目录图片也统一编号，避免裸文件名影响排序，且解决扁平导出中的同名图片冲突。只有导出名称改变，项目内原文件名和存储对象不变。

未手动排序的导出维持旧命名。单独导出翻译文本也使用同一编号规则；与既有图片包配套使用时，应保持两次导出的图片选择范围一致。
