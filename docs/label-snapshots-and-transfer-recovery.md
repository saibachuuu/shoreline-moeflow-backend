# 标签快照与迁移操作说明

## 标签快照

- 保存所有文件修订的 Source / Translation / Tip 原始字段：坐标、原文、全部语言及作者的译文、校对、选定者、机翻标记、批注和时间。内部代际字段不属于存档内容。
- 不备份图片、目标语言配置、权限或导出文件。快照关联文件/语言被删除、替换后不能恢复；新增文件保留，但新增标签会被全覆盖清空。
- 使用数据库分块（每块 4 MiB）及 SHA-256 校验；仅完整发布的快照可读取。没有自动清理历史快照的保留策略，应监控数据库容量。
- 恢复、空存档清空、合并都先创建全量保护快照。合并仅当前语言，批注保留；清空校对不改变选定状态，可独立清除批注。清空上游栏位级联所有语言/作者的下游数据。
- 管理项目成员的人员可完整恢复/清空；校对权限可清空校对；合并还需要选定和新增译文权限。快照创建还允许校对或导出权限。
- 批量操作后页面重新加载。旧模型对象与旧页面版本拒绝写入；标签 API 在项目首次批量操作后要求 `X-Label-Revision`（先 GET 取得响应头）。
- 排队的文本解析、术语匹配、OCR、LabelPlus/档案导入携带入队时的标签版本；恢复后旧任务即使重新加载模型也不能写回。旧消息没有版本字段时按版本 0 处理；被版本保护跳过的任务需重新发起，不自动重放。并行的普通读写最多等待项目锁 2 秒，持续占用时返回冲突，避免读到半恢复的数据。

## 异常恢复与锁

锁集合为 `project_label_lock` / `storage_transfer_run_lock`，`_id` 分别为项目 / 迁移 ObjectId，`owner` 为本次持有者。**锁不设 TTL**：超时并不代表旧进程已停止，自动解锁可能允许两个 writer 并发破坏数据。

正常异常会释放锁。进程被杀死时按以下步骤人工处置：

1. 暂停迁移扫描/执行；停止 API、所有 Celery worker 和相关脚本，确认没有仍可能写入的旧进程。只暂停队列或等待超时不够。
2. 备份数据库。检查指定锁的 `_id`、`owner` 与迁移阶段；不得批量删除锁集合。
3. 仅在所有旧 writer 已停止的前提下，按 `_id` **及**已核实的 `owner` 条件删除那一条遗留锁。保留项目 `label_recovery` 标记和全部快照。
4. 标签存在 `label_recovery` 时，恢复 API 后由项目管理员在“读取快照”窗口点击“恢复保护快照”；普通写入仍被阻止。恢复失败保留标记，排查快照完整性/文件关联后再处理，禁止直接清标记。
5. 迁移保持原状态续跑；FAILED/ABORTED 必须经重试 API，COPYING/VERIFIED/SWITCHED 使用原任务 ID 继续执行，不重新创建搬运记录。

## 迁移队列与容量

- 仅 PENDING 可原子取消；已经搬运/校验/切指针的任务不可删除队列。取消记录可删除；DONE 且无残留警告可删除历史记录，同时删对象清单，绝不删存储对象。
- 原图/导出缺失视为失败，缺失重采样图可跳过。处理数包含跳过数；复制完成不是整体完成，校验/切换/清理结束才为 100%。源端残留警告保留记录供人工清理。
- 切指针前按验证过的对象大小校正原图/重采样图/导出，并重算逻辑数量。逻辑数量仅活动修订；容量包含仍有实物的历史修订，不重复计目录汇总。
- `File.file_size` / `Project.file_size` 是历史 KB 字段，因此原件容量仍有 KB 精度；派生图和导出以精确 bytes 汇总。项目总量不等于本次迁移量（封面、文本等仍在默认存储）。

## 手动容量回填

先在正确的本地/受控配置下运行脚本的 dry-run：

```sh
python -m app.scripts.backfill_storage_usage --project-id PROJECT_ID --recalculate
python -m app.scripts.backfill_storage_usage --project-id PROJECT_ID --recalculate --apply
python -m app.scripts.backfill_storage_usage --project-id PROJECT_ID --only totals --apply
```

`--recalculate` 也校正非零容量；`--only totals` 不探测存储，只从已有字段重算。`total_bytes` 包括原件、封面、重采样图和导出产物，最后才换算项目 KB。HEAD 网络/权限错误不归零，重采样图仅 404 时尝试历史默认存储。探测期间文件键或存储指针改变会拒绝应用旧结果。

对象容量字段和项目汇总不是跨集合事务；apply 中途退出后须重跑（至少 `--only totals --apply`）。dry-run 的总量日志反映数据库已有容量，不是未写入探测结果的预测。
